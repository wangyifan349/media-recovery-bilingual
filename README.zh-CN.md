# 🔎 媒体数据恢复 · 中文 & English

🌐 **语言 / Language：** [🇨🇳 简体中文](README.zh-CN.md) ⇄ [🇬🇧 English](README.md)

这是一个 Python 3 **原始镜像只读文件特征提取工具**，提供中英文桌面界面、可选导出后校验、状态文件名前缀和离线图片预览。

> ⚠️ 本工具是实验性恢复辅助程序，**不是保证恢复成功或修复损坏文件的产品**。它从镜像中提取可辨认、连续存放的字节范围，不能判断文件是否已删除。检查通过不证明内容与删除前完全一致。

## 🛑 1. 首先保护原盘

1. 停止使用丢失数据所在的物理磁盘。不要在该盘安装项目或依赖、下载文件、运行文件系统修复或保存恢复结果。
2. Python、项目、镜像和输出都应放在**原物理磁盘以外**的健康存储上。不同分区或盘符可能属于同一硬盘；程序不会自动识别物理磁盘是否相同。
3. 用可靠的镜像工具制作逐扇区的**原始字节镜像**，再扫描副本。本程序不制作镜像。E01、VHD/VHDX、QCOW2 或压缩容器需要先正确转换为原始字节；改扩展名不等于转换。
4. 对异响、掉线或故障硬盘不要反复扫描。重要数据优先咨询专业恢复服务。

SSD TRIM、覆盖、加密和碎片化都可能让数据无法恢复。“我没有写入”不保证数据仍可恢复。只读文件句柄不能替代取证写保护器；操作系统仍可能更新访问元数据。

## 🚀 2. 启动中文或英文版

需要 **Python 3.10+**。图形界面还需要 Tkinter 和可用的图形显示环境。Windows/macOS 的 Python 发行版通常包含 Tk；Linux 可能需要单独提供 Tk 组件。命令行扫描不会导入 Tkinter。

解压 ZIP 后，在 **`media_recovery` 文件夹内部**打开终端；或进入克隆后的仓库。下文所有命令均在该目录执行：

```bash
python start_en.py                 # 英文版
python start_zh.py                 # 中文版
python start.py --language en      # 显式选择英文
```

两个入口使用**同一套恢复和校验逻辑**，不是独立维护的两份程序。没有任务运行时，可在“语言”菜单切换界面，保留路径、设置和已载入结果。系统文件对话框及第三方错误信息可能遵循系统或库的语言；用户路径和文件名不会被翻译。

源码包不含第三方库，不会自动安装、不需要账户登录、不含遥测，也不由程序主动发起网络请求。这些说明仅针对程序本身，不包含操作系统或你启动的浏览器、查看器的行为。

### 📦 可选依赖——仅在你选择时自行安装

核心提取和 PCM WAV 检查使用 Python 标准库。已具备相应依赖时才启用以下可选校验：

```bash
python -m pip install -r requirements.txt
```

| 组件 | 用途 | 缺少时 |
| --- | --- | --- |
| Pillow | 图片识别、完整性检查、所有暴露帧/页解码及缩略图 | 仍能恢复，图片标为 `UNVERIFIED` |
| miniaudio | 流式解码受支持的 MP3、FLAC、Ogg Vorbis 和非 PCM WAV | PCM WAV 仍使用 `wave`，其他音频不充分验证 |
| `pillow-heif`（另行可选安装） | 安装后自动注册 HEIC 插件 | 仍可提取 HEIC，但可能无法解码 |
| `PATH` 中的 FFmpeg 可执行程序（另行可选提供） | 仅用于视频解码校验 | 视频标为 `UNVERIFIED` |

**音频绝不调用 FFmpeg 或 Windows 专属音频组件。** miniaudio 跨平台，但包含原生代码和 CFFI，**不是纯 Python**；Pillow 也包含原生组件。离线安装依赖需要适合 Python/操作系统的 wheel 及其依赖，源码 ZIP 不包含它们。AVIF 解码能力取决于安装的 Pillow 构建及编码支持。

## 🖱️ 3. 图形界面流程

1. 选择 `.img`、`.dd`、`.raw` 或其他普通原始镜像文件。程序刻意不支持设备路径或直接访问物理磁盘。
2. 勾选格式选择器。**MP4** 同时扫描下表所列 ISO-BMFF 变体；**OGG**、**MKV**、**ZIP** 也覆盖其对应扩展格式。
3. “只读扫描”在日志列出候选偏移和大小，不导出，**不做解码校验或生成预览**，但仍可能消耗较多时间和磁盘 I/O。
4. 选择安全输出目录，点击“恢复并检查”，确认输出不在原物理磁盘上。取消“恢复后自动校验”会把导出标为 `UNVERIFIED`。
5. 按状态筛选、选择图片缩略图，或在任务结束/停止后打开离线预览。打开选中媒体需要确认，并使用系统查看器；其他文件类型不会自动打开。

“停止”以协作方式取消扫描/导出，并终止正在运行的解码子进程。保留已完成文件，删除正在导出的半成品。查看器占用文件可能导致重命名失败，Windows 尤其常见。本程序不支持断点续扫，重新运行会创建新会话。

## 🧩 4. 格式覆盖——部分变体，不代表所有编码

共有 **21 个公开扫描选择器**，可输出多种扩展名。下表分开说明候选识别与内容验证。结构检查是有意限定范围的：候选可能误报或损坏，损坏/特殊布局的原文件也可能完全漏检。

| 选择器 | 候选扩展名 | 边界和结构检查 | 可选导出后校验 |
| --- | --- | --- | --- |
| `jpg` | `.jpg` | JPEG 标记、段长度、帧/扫描存在性；转义字节及 EXIF 段边界 | Pillow |
| `png` | `.png` | 签名、基本 IHDR、块、CRC、IDAT/IEND | Pillow |
| `gif` | `.gif` | GIF87a/89a、色表、块链、结束标记 | Pillow，在限制内检查所有帧 |
| `bmp` | `.bmp` | 部分 DIB 头长度、声明长度和像素偏移 | Pillow |
| `ico` | `.ico` | 图标目录及引用数据范围 | Pillow 暴露的图像；**不保证解码每个内嵌尺寸** |
| `tif` | `.tif` | 经典小端/大端 TIFF IFD、部分引用和 strip/tile 范围 | Pillow，在限制内检查暴露的页面 |
| `webp` | `.webp` | RIFF 长度/块边界及 WebP 块存在性 | Pillow |
| `wav` | `.wav` | RIFF/WAVE、fmt/data、长度及填充 | 受支持 PCM 用标准库 `wave`，其他兼容编码可用 miniaudio |
| `mp3` | `.mp3` | 可选 ID3v2 前缀，至少 3 个连续 MPEG **Layer III** 帧；可选 ID3v1 | miniaudio；边界为推断 |
| `flac` | `.flac` | 已知且非零样本总数的 STREAMINFO、元数据、受支持子帧/Rice 残差、头/帧 CRC | miniaudio；**不校验 STREAMINFO 中的 PCM MD5** |
| `aac` | `.aac` | 至少 3 个连续 ADTS 帧 | 仅结构检查，未集成完整 AAC 解码器 |
| `amr` | `.amr` | AMR-NB/WB 标识和部分语音/SID 帧类型 | 仅结构检查，未集成完整 AMR 解码器 |
| `ogg` | `.ogg`、`.opus` | Ogg 页边界、序号/序列号、CRC、EOS；OpusHead 扩展名提示 | miniaudio 检查受支持 Ogg Vorbis；Opus 仅结构检查 |
| `aiff` | `.aiff` | AIFF/AIFC FORM、COMM/SSND 和块边界 | 仅结构检查 |
| `au` | `.au` | AU 头、已知数据长度和基本参数 | 仅结构检查 |
| `mp4` | `.mp4`、`.mov`、`.m4a`、`.3gp`、`.heic`、`.avif` | 部分 ftyp 品牌、允许的连续 box；基本 moov/mdat 或 meta/mdat | 视频用 FFmpeg；图片用 Pillow/插件；M4A 仅结构检查 |
| `avi` | `.avi` | 一个 RIFF AVI 范围、顶层块边界及 LIST 存在性 | FFmpeg；不重组 AVI/OpenDML 延续段 |
| `mkv` | `.mkv`、`.webm` | EBML DocType 提示和**有限长度** Segment | FFmpeg；拒绝未知长度 Segment |
| `flv` | `.flv` | 头、部分 tag 类型、长度及 PreviousTagSize | FFmpeg；边界为推断 |
| `pdf` | `.pdf` | 头和附近带 `startxref` 的首个 `%%EOF` | 仅结构检查；可能恢复较早增量版本，而不是最新文档 |
| `zip` | `.zip`、`.docx`、`.xlsx`、`.pptx`、`.epub` | EOCD 和中央目录；按成员名推测扩展名 | 标准库成员读取/CRC；**不验证 Office/EPUB 文档语义** |

重要的不支持项和歧义：

- 不解析 NTFS/FAT/exFAT 元数据，不区分已删/现存文件，不恢复原文件名/路径/时间戳，不重组文件系统碎片，不抢救坏扇区、不解密卷、不修复损坏媒体。
- ISO-BMFF 没有统一结束标记：可能把相邻的似合法 box 合并进候选；未知或 size=0 box、缺失 `moov` 可能导致漏检/截断。仅识别部分 MOV/3GP/HEIC/AVIF 布局，不保证恢复碎片化 MP4。
- MP3/AAC/AMR/FLV 从连续结构推断结束位置；填充或无关字节可能被误认成后续帧。设置文件上限也可能使启发式格式产生不完整候选。能解码不证明找回了原结尾。
- 不支持未知/零样本总数 FLAC、BigTIFF、任意相机 RAW 布局、ZIP64、分卷 ZIP。ZIP 衍生扩展名只是提示，不是权威文档类型判断。
- 成功候选会抑制重叠/内嵌候选。不会单独导出已接受容器中的内嵌缩略图或文件；只复制连续字节。

## ✅ 5. 状态、预览与校验限制

| 前缀 | 含义 | **不**代表 |
| --- | --- | --- |
| `OK__` | 实现的解码/读取/CRC 检查未发生指定失败并完成 | 完美恢复、与原内容一致、语义正确、所有编码特性已检查或无恶意内容 |
| `DAMAGED__` | 受支持检查发现具体内容错误、空解码或数据不足 | 其他所有文件都已充分检查 |
| `UNVERIFIED__` | 无兼容解码器、缺依赖、不支持编码、跳过、超时、安全限制或失败原因不确定 | 一定损坏或一定可用 |

检查能力取决于库报告的结果。解码器可能隐藏错误或接受截断但仍能解码的内容。miniaudio 样本数对比允许 **8192 个交错样本**的容差，不是精确原始长度验证。PCM WAV 只检查声明帧的字节数，不判断听起来是否正常。

安全/超时限制：

- 图片：最多 **1000 个暴露帧/页**、累计 **150,000,000 像素**，还受 Pillow 解压炸弹检查约束。ICO 可能仅暴露默认选中尺寸。第一暴露帧/页用于缩略图。
- ZIP：最多 **10,000 个成员**、声明解压总量 **512 MiB**。不校验加密内容。成员仅读取校验 CRC，**绝不解压到文件系统**。
- 每文件解码子进程默认限时 **120 秒**；超时或取消会终止并回收。这是实用检查，**不是操作系统安全沙箱**，也不是严格内存/CPU 配额。应使用可信且更新的解码库，谨慎处理不可信文件。
- 默认扫描缓冲区 **8 MiB**，但校验器缓冲、候选记录和 GUI 结果/历史列表还会占用内存。无限结果下不是恒定内存程序。GUI 拒绝载入超过 64 MiB 的历史清单。

## 📁 6. 输出与审计记录

每次导出创建新的 `recovered_<UTC时间戳>_<随机标识>` 目录：

```text
recovered_.../
├── OK__offset_0000000000001000.png
├── UNVERIFIED__offset_0000000000009000.mp4
├── manifest.jsonl
├── preview.html          # 所选语言
├── preview_en.html       # 英文预览
├── preview_zh.html       # 中文预览
└── previews/             # 可生成时保存图片缩略图
```

文件名记录**源镜像字节偏移**，不是原文件名。三个 HTML 文件都是离线预览，无 JavaScript 或远程资源；切换语言不会重复复制媒体。

`manifest.jsonl` 按行保存 JSON，以追加为主。开始记录包含源路径/大小、选择器、候选大小上限、语言和清单版本。导出记录包含偏移、大小、扩展名、结构检查标识、SHA-256、稳定状态码、中英 `detail_en`/`detail_zh`、所选语言 `detail` 和可选预览路径。在可写入时以 `complete`、`cancelled` 或 `error` 结束。没有 `complete` 时，**不可视为扫描完成**。断电或强制终止可能留下不完整末行或未登记文件；它不是崩溃安全事务日志。

SHA-256 标识导出字节，不证明等于删除前原文件。清单中的源路径可能涉及隐私，请勿公开真实恢复输出。预览写入失败不一定使已导出媒体失效。兼容旧版仅有 `detail` 的清单，但无法追溯翻译它们原有的说明。

## ⌨️ 7. 命令行

下面路径仅为占位示例，请替换成安全的源和输出位置：

```bash
python recover.py --language en "/safe/images/disk.img" --dry-run
python recover.py --language en "/safe/images/disk.img" --output "/other-disk/recovered"
python recover.py --language zh "/safe/images/disk.img" --output "/other-disk/recovered"
python recover.py --language en "/safe/images/disk.img" -o "/other-disk/recovered" --types jpg,png,flac,mp4
python recover.py --language en "/safe/images/disk.img" -o "/other-disk/recovered" --max-file-mib 16384 --verify-timeout 300
python recover.py --language en --help
```

Windows 可以使用 `"E:\images\disk.img"`、`"F:\Recovered"` 一类路径，**但必须先确认对应物理磁盘安全**。

| 参数 | 默认值 / 行为 |
| --- | --- |
| `image` | 命令行扫描必需的原始镜像文件 |
| `-o`、`--output` | 除 `--dry-run` 外必需 |
| `--language en\|zh` | `zh`；选择程序消息及主预览语言 |
| `--types` | `all`；用逗号分隔上表公开选择器 |
| `--max-file-mib` | `4096`；单候选上限，1 MiB = 1,048,576 字节 |
| `--chunk-mib` | `8`；正整数扫描块大小 |
| `--verify-timeout` | `120`；每文件正整数秒数 |
| `--no-verify` | 导出并标 `UNVERIFIED__`，不做解码 |
| `--dry-run` | 仅扫描和日志，不导出、不生成清单/预览 |
| `--gui --language en` | 启动图形界面，不与扫描参数混用 |

命令行退出码：`0` 扫描完成（不证明恢复成功），`1` 运行错误，`2` 参数错误，`130` 协作式取消。无参数执行 `recover.py` 启动中文界面。程序不能阻止访问时间更新或其他进程更改镜像，扫描期间请保持镜像不变。

## 💾 9. 在需要恢复之前，先养成备份习惯

- **🗂️ 多副本，也要多介质。** 可以参考 **3–2–1**：包括工作副本在内共三份，至少使用两类存储，其中一份独立存放或异地保存。例如：日常文件、带历史版本的移动硬盘备份，以及一份独立异地副本。对不可替代的数据，单一云端账户或一块移动硬盘都不够。
- **⏱️ 及时备份，并定期执行。** 新拍的照片、录音、重要文档在创建或导入后尽快备份。设定计划，还要检查计划任务是否真正完成；保留旧版本，不要反复覆盖唯一的完好副本。
- **🔄 同步不等于备份。** 删除和错误修改也可能被同步。确认服务的历史版本、删除保留期限和恢复方式；另存一份独立副本，不要仅依赖云同步。
- **🔌 留一份断开连接或隔离的副本。** 不需要时断开备份硬盘，不要让所有副本始终连接在同一设备上，降低一次误操作或故障影响全部副本的风险。
- **🛡️ 降低误改风险。** 条件允许时，为整理完毕的归档设置只读权限，限制备份目录的写入权限。普通只读权限可能被更改，或被高权限软件绕过；它能减少误操作，但**不能代替断开连接、独立保存的备份**。
- **✅ 定期检查，也要试恢复。** 抽样打开文件，对比数量、大小或可信校验和，把少量文件恢复到临时位置验证。显示“复制成功”不证明备份完整、可读或能恢复；介质老化时也要确认其他副本仍可访问。
- **🏷️ 先整理确认，再删除。** 使用清晰的日期目录和有意义的文件名，简单记录各份备份放在哪里，谨慎处理重复文件。在删除原件或大规模整理前，至少确认一份独立且经过验证的副本。

> 🌱 最好的恢复准备，是一份较新、独立且验证过的备份。这个工具是误操作后的补救，不是备份的替代品。
